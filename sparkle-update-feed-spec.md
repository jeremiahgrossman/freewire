# Freewire VPN — Sparkle Update Feed Specification

**Audience:** macOS engineers and DevOps  
**Version:** 1.0  
**Last updated:** 2026-06-17  
**Applies to:** macOS direct download path only. App Store builds use Apple's own update mechanism.

---

## Overview

Sparkle is the macOS auto-update framework used by the Freewire direct download app. When the app launches, it checks for updates at the appcast URL, compares versions, and offers (or silently installs) updates.

This document specifies the appcast XML format, hosting, signing, and update categories.

---

## Appcast URL

```
https://freewire.com/appcast.xml
```

This URL must be stable — it is hardcoded in the app bundle's `Info.plist` (`SUFeedURL` key) and cannot change without shipping an update. The HTTPS certificate for `freewire.com` must be valid; Sparkle rejects appcast fetches over HTTP or with invalid certificates.

The appcast is hosted on Freewire's CDN (same infrastructure as the DMG downloads). It must be globally accessible with low latency — Sparkle checks it on every app launch.

---

## Signing

All Sparkle updates must be signed with an **EdDSA (Ed25519) keypair**. Sparkle verifies the signature before applying any update. An update with an invalid or missing signature is rejected.

**Key generation (one-time setup):**
```bash
# Using Sparkle's generate_keys tool
./bin/generate_keys
# Outputs:
#   Private key: (save securely — this is SPARKLE_ED_PRIVATE_KEY in CI secrets)
#   Public key:  (embed in app's Info.plist as SUPublicEDKey)
```

The **public key** is embedded in the app bundle at build time (`SUPublicEDKey` in `Info.plist`). It never changes — changing it would require users to manually update (which breaks the entire update chain).

The **private key** is stored only in CI secrets (`SPARKLE_ED_PRIVATE_KEY`). It is never committed to the repository. Loss of the private key means new updates cannot be delivered via Sparkle — keep a secure backup.

**Signing an update:**
```bash
./bin/sign_update Freewire-1.2.3.dmg $SPARKLE_ED_PRIVATE_KEY
# Outputs the sparkle:edSignature value to embed in the appcast item
```

## Appcast XML Format

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0"
     xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle"
     xmlns:dc="http://purl.org/dc/elements/1.1/">
  <channel>
    <title>Freewire</title>
    <link>https://freewire.com</link>
    <description>Freewire VPN updates</description>
    <language>en</language>

    <!-- Most recent release first -->
    <item>
      <title>Freewire 1.2.3</title>
      <link>https://freewire.com/release-notes/1.2.3</link>
      <sparkle:version>47</sparkle:version>
      <sparkle:shortVersionString>1.2.3</sparkle:shortVersionString>
      <sparkle:releaseNotesLink>https://freewire.com/release-notes/1.2.3</sparkle:releaseNotesLink>
      <pubDate>Wed, 17 Jun 2026 12:00:00 +0000</pubDate>
      <sparkle:minimumSystemVersion>13.0</sparkle:minimumSystemVersion>
      <sparkle:criticalUpdate sparkle:version="45"/>
      <enclosure
        url="https://cdn.freewire.com/downloads/Freewire-1.2.3.dmg"
        sparkle:version="47"
        sparkle:shortVersionString="1.2.3"
        sparkle:edSignature="AAABBBCCC...base64-ed25519-signature..."
        length="12345678"
        type="application/octet-stream"/>
    </item>

    <!-- Previous release retained for rollback reference — not used by Sparkle directly -->
    <item>
      <title>Freewire 1.2.2</title>
      ...
    </item>

  </channel>
</rss>
```

### Required fields per item

| Field | Description |
|---|---|
| `sparkle:version` | The build number (`CFBundleVersion`). Must be a monotonically increasing integer. Sparkle uses this, not the human-readable version, to determine whether an update is newer. |
| `sparkle:shortVersionString` | Human-readable version string (`CFBundleShortVersionString`). Displayed to the user. |
| `sparkle:edSignature` | EdDSA signature of the DMG file, base64-encoded. Generated by `sign_update`. |
| `enclosure url` | Direct HTTPS URL to the DMG. Must be a stable URL that doesn't change after publication. |
| `enclosure length` | File size in bytes. Sparkle uses this to show download progress. |
| `sparkle:minimumSystemVersion` | Minimum macOS version required. Match the deployment target in the Xcode project. |

### Critical updates

`<sparkle:criticalUpdate sparkle:version="N"/>` marks an update as critical if the user's installed version is at or below build `N`. Sparkle shows a more urgent UI and may not allow the user to dismiss the prompt.

Use critical update for:
- Security fixes
- Fixes for bugs that cause data loss or privacy exposure
- Protocol updates required by a breaking server change (coordinate with the major version transition window)

---

## Update Categories

Freewire distinguishes between security and non-security updates in the error states spec (UPDATE-1). The appcast does not have a formal "security" flag — the distinction is communicated via:

1. **`sparkle:criticalUpdate`** — marks the update as requiring prompt attention
2. **Release notes** — state clearly "This is a security update" when applicable

---

## Hosting Requirements

The appcast and DMG files are hosted on `cdn.freewire.com` (CloudFront or equivalent CDN):

- **Appcast TTL:** 1 hour. Sparkle caches the appcast; a short TTL ensures updates reach users promptly.
- **DMG TTL:** 1 year (immutable — a DMG at a given version URL never changes).
- **HTTPS required:** Both appcast and DMG URLs must be HTTPS with a valid certificate.
- **Availability SLA:** Match managed server uptime (≥99.5%). If the CDN is down, Sparkle fails silently and retries on next launch — existing app continues to work.

---

## Appcast Update Script

The build pipeline runs `scripts/update_appcast.py` after each macOS release. The script:

1. Downloads the current `appcast.xml` from the CDN
2. Prepends a new `<item>` for the new release (with correct version, URL, file size, and EdDSA signature)
3. Retains the last 5 releases in the appcast (older items are removed)
4. Uploads the updated `appcast.xml` to the CDN

The script requires:
- `SPARKLE_ED_PRIVATE_KEY` (from CI secrets)
- The built DMG path
- The version and build number
- AWS credentials to upload to the CDN bucket

## Sparkle Configuration in Info.plist

```xml
<!-- Appcast URL -->
<key>SUFeedURL</key>
<string>https://freewire.com/appcast.xml</string>

<!-- EdDSA public key for signature verification -->
<key>SUPublicEDKey</key>
<string>BASE64_ENCODED_ED25519_PUBLIC_KEY</string>

<!-- Check for updates automatically -->
<key>SUEnableAutomaticChecks</key>
<true/>

<!-- Allow automatic download but require user confirmation to install -->
<key>SUAutomaticallyUpdate</key>
<false/>

<!-- Do not send system profile to Sparkle's servers -->
<key>SUSendProfileInfo</key>
<false/>
```

`SUAutomaticallyUpdate` is `false` — the app downloads the update in the background but shows a one-click install prompt. Fully silent installs (without any user interaction) are not used, as VPN apps benefit from users knowing when the tunnel software has changed.
